Privacy Policy

Effective date: 11 November 2026

This policy explains how the AI Personalized Learning & Study Planner project and its database backup utility handle information. This is a software development project. This policy must be reviewed and updated if the project is opened to additional users or its data practices change.

1. Information handled

Depending on features used, the application database may contain information entered into the learning planner, such as student profile details, subjects, topics, study plans, learning resources, quiz responses, and performance records.

The backup utility creates SQL dump files from the configured MySQL database. Those files may contain records stored in that database. Operators are responsible for ensuring they have authority to process and back up the information in their database.

2. Google Drive access

The backup utility can connect to Google Drive using Google's OAuth authorization. It requests the https://www.googleapis.com/auth/drive.file scope. This scope allows the application to create and manage files it creates or files the user specifically makes available to it; it does not request general access to all files in the user's Drive.

When cloud backup is enabled, database backup files are uploaded to the configured Google Drive backup folder. The utility may list, inspect, download, and move its backup files to Google Drive trash as part of backup management and retention.

3. OAuth credentials and tokens

In the current project configuration, OAuth client credentials are stored in the project's secrets directory and the user token is stored in a local token file. These files must remain private, be excluded from public source control, and be protected with appropriate operating-system permissions.

Never publish OAuth client secrets, access tokens, refresh tokens, database passwords, or backup files in the public repository. Google Drive access can be revoked through the Google Account security settings or connected-app permissions.

4. How information is used

Database contents are used by the learning planner features. Backup files are used to preserve and restore the configured database. Google Drive is used as the cloud storage destination when the operator enables cloud backups.

This policy describes the intended functions of the project. It must be updated if analytics, advertising, additional integrations, or other data processing are introduced.

5. Storage and retention

Local SQL backups are stored in the configured local backup directory. Cloud backups are stored in the configured Google Drive folder. The current cloud retention workflow is configured to retain backups across up to seven distinct backup dates and may move older matching backup files to Google Drive trash. Actual retention depends on the running configuration and successful execution of the workflow.

Google Drive storage is also subject to Google's terms, privacy policy, and account settings. The project maintainer does not control Google's infrastructure or retention of items after they are moved to trash.

6. Sharing and third parties

The backup utility sends backup files to Google Drive when cloud backup is enabled. Google processes those files to provide its storage and API services. The project does not intentionally sell database contents or share them with advertising providers. Do not use the application with personal or sensitive information unless you have authority and appropriate safeguards.

7. Security

The project uses OAuth for Google Drive authorization and validates downloaded backup files using file size, SHA-256 checksums, and SQL backup validation. These measures help detect certain integrity problems but do not guarantee absolute security. Operators should restrict access to the computer, repository, database, OAuth files, and Google Drive folder, and maintain independent recovery copies where appropriate.

8. Data deletion and revoking access

Operators can delete local backup files and delete or move cloud backup files to Google Drive trash using the relevant storage controls. Operators can revoke application access from Google Account security settings. Deleting a backup does not automatically delete corresponding records from the live MySQL database, and deleting database records does not automatically remove existing backup copies.

9. Children's information

This project is not presented here as a service directed to children. If adapted for minors or schools, the operator must assess and meet applicable consent, notice, and data-protection requirements before collecting or processing their information.

10. Changes

This policy may be updated when project functionality or data practices change. The effective date at the top of this page will be revised when material changes are made.
